- Purgeable versus immediately reclaimable space
- Reserve needed for macOS updates
- Reserve needed for the user’s recent maximum swap usage
- Sudden free-space loss
- Space that returns without cleanup, indicating churn
- Space that fails to return after deletion
- Per-volume read-only state
- Capacity runway based on growth, not only a static percentage

Suggested logic:

- Warning: below 15–20%, adjusted for drive size
- Critical: below 10% or an absolute minimum
- Emergency: projected exhaustion within several days
- Separate alert: sudden loss of many gigabytes, even when substantial space remains

## 16. Backup and restoration readiness

**[ADDED, HIGHEST PRIORITY]**

A soldered SSD makes backup readiness more important than predicting endurance.

Monitor:

- Whether Time Machine is configured
- Last successful external backup
- Age of the last successful backup
- Current backup status
- Backup failures
- Backup destination availability
- Backup destination free space
- Backup encryption
- Whether important directories are excluded
- Whether backups can be verified
- Whether a recent restore test has succeeded
- Whether a second independent backup exists
- Whether critical repositories exist somewhere off the Mac
- Whether the only recovery copies are local APFS snapshots

Local snapshots reside on the same internal drive. They are useful for version recovery but do not protect against total device failure. Apple recommends a backup located outside the internal disk. [Apple Time Machine guidance](https://support.apple.com/en-us/104984), [Apple local-snapshot guidance](https://support.apple.com/en-euro/guide/mac-help/mh35933/mac)

Suggested severity:

- Critical: no backup configured
- Critical: repeated backup failures
- Critical: no verifiable external backup for a user-defined maximum period
- Warning: destination unavailable
- Warning: backup too old
- Warning: backup destination nearly full
- Warning: restore has never been tested

## 30. Evidence and diagnostic honesty

**[DOCUMENT PRINCIPLE, ADDED AS PRODUCT REQUIREMENT]**

Every finding should be labeled:

- **Measured:** Direct operating-system or drive counter
- **Derived:** Rate, trend, or forecast calculated from measurements
- **Correlated:** Two events occurred together
- **Inferred:** Likely cause, but not proven
- **Reported:** Known external failure mode not reproduced locally
- **Unavailable:** Could not be measured

For example:

- “Swap increased by 12 GB” is measured.
- “Swap likely contributed to SSD writes” is inferred.
- “Cursor wrote 4 GB during the same interval” is correlated.
- “The SSD is dying” requires actual drive-health evidence.

# Recommended Dashboard Domains

Do not collapse everything into one grade. Present independent statuses:

1. **Data-loss readiness**
2. **SSD physical health**
3. **Storage headroom**
4. **Memory and swap pressure**
5. **Disk-write activity**
6. **Process lifecycle**
7. **Agentic-state growth**
8. **Thermal and performance health**
9. **Agent runaway and destructive-action risk**
10. **Privacy and retention**
11. **Backup and restoration**
12. **Monitor reliability**

A green SSD score must never conceal a red backup or filesystem warning.

# Highest-Priority Implementation Order

If building this in stages, the essential order is:

1. Backup success and restoration readiness
2. NVMe Critical Warning, errors, read-only state, and endurance
3. Storage headroom, growth, and exhaustion forecast
4. Memory pressure, swap amount, and swap rate
5. Process-tree leaks and orphaned agents
6. System and per-process write storms
7. Agentic state, databases, snapshots, and regeneration
8. Uncommitted-work and destructive-action protection
9. APFS and filesystem errors
10. Privacy, retention, and secret-exposure configuration
11. Thermal pressure and stability
12. Battery, energy, network, and cost monitoring

That is the complete monitoring surface suggested by the article, expanded into a tool that protects against actual disasters rather than merely reporting SSD write totals.
